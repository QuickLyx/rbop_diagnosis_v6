# v6 云端运行说明（Cloud Studio + 远端 T4）

> 目的：把这个目录整个 clone 到云端 GPU 机器上就能跑完第一轮 96 个运行单元，不用再去别的目录找数据和权重。
> 协议与判据不在这里改，见 `docs/v6协议草案.md` 与 `docs/v6运行冻结记录.md`。

## 1. 仓库里已经自带什么

| 内容 | 大小 | 说明 |
| --- | ---: | --- |
| `Data/` | **657 MB**，161 个 `.mat` | 从 `rbop_diagnosis_v4/Data` 逐字节复制：`Normal` 4、`12k_DE` 60、`12k_FE` 45、`48k_DE` 52（源侧枚举时自动排除 028 档，文件仍保留） |
| `weights/v5_joint/` | **42 MB** | 12 个 `f{fold}_s{seed}_joint/{last.pt,config.json}`，即所有臂的起点权重；复制时逐文件比对过 sha256，与 v5 原目录一致 |
| `outputs/v6_round1/selection/selection.json` | 46 KB | **已冻结标注池**（`12k_FE` k=K=10、`48k_DE` k=K=12），云端只读不改 |
| `outputs/v6_round1/frozen_plan_v6.json` | 6 KB | 冻结计划（判据、六对配对链、逐折预算） |
| 代码 8 个模块 + `run_v6.sh` + `requirements.txt` + `docs/` | <0.5 MB | — |
| `.gitignore` | — | 排除 `outputs/v6_round1/train/`（约 300 MB 权重）、日志与 `_smoke/` |

仓库合计约 **700 MB**，单文件最大 17 MB（`.mat`）与 3.5 MB（`.pt`），都在 GitHub 单文件 100 MB 限制之内。

## 2. 环境

```bash
python -V                                  # 3.9 以上都行（本机在 3.13.9 验证）
pip install -r requirements.txt            # 只用到 torch / numpy / scipy / scikit-learn
# T4 建议直接装 CUDA 版 torch：
pip install torch --index-url https://download.pytorch.org/whl/cu124
python -c "import torch;print(torch.cuda.is_available(), torch.cuda.get_device_name(0), torch.__version__)"
```

装包只需这四个：训练与评估不用 pandas（CSV 走标准库 `csv`），`.mat` 用 `scipy.io.loadmat` 就能读（无 v7.3 文件）。

## 3. 把仓库弄上云端（三选一）

1. **直接 git 提交（最省事，推荐第一次这么干）**
   ```bash
   cd rbop_diagnosis_v6
   git init && git add -A && git commit -m "v6 round1: 冻结池+代码+数据+起点权重"
   git remote add origin <你的仓库地址> && git push -u origin master
   ```
   700 MB 一次推完，慢但一次成功；云端 `git clone` 后就是完整可用环境。
2. **`Data/` 与 `weights/` 走 Git LFS**（仓库要长期迭代、反复 push 时更合适）：
   `git lfs install && git lfs track "*.mat" "*.pt"`，然后再 `git add -A`。云端必须也装了 git-lfs，否则 clone 下来是 LFS 指针文件。
3. **不进 git，直接传**：把 `Data/`、`weights/` 打包（`tar czf v6_assets.tgz Data weights`）通过 Cloud Studio 的文件上传放到项目根目录解压，代码单独用 git 管。适合 push 不稳或免费额度带宽受限的情况。

无论走哪条，落地后要能看见 `Data/12k_FE`、`weights/v5_joint/f0_s0_joint/last.pt`、`outputs/v6_round1/selection/selection.json` 三样东西都在（`run_v6.sh` 开头会替你检查，缺了立刻退出）。

## 4. 云端第一步：三条自检命令

```bash
python dataset.py && python preprocessing.py && python model.py && python trainer.py && python experiment.py
bash run_v6.sh status
bash run_v6.sh one ce_adapt 12k_FE 0 0 smoke      # 约 4 分钟，产物进 _smoke/，不计入正式结果
```

- 前一条是各模块自检（数据枚举、四折、表征形状、采样均衡、起点与预算）。
- `status` 打印 `完成 n/96 个单元｜下一个：…`，同时会做前置检查（数据目录、12 个起点权重、冻结池）并打印检测到的 GPU。
- `one … smoke` 是完整跑一遍"训练 30 轮 + 留出评估"的管道检查：能在 GPU 上跑通、能落 `last.pt/config.json/history.csv/split.json/target_split.json`、能出 `metrics.json/predictions.csv/eval_info.json`，再开全跑。

## 5. 跑全批与看进度

```bash
mkdir -p outputs/v6_round1/logs
nohup bash run_v6.sh all 2>&1 | tee -a outputs/v6_round1/logs/run_v6.log &
tail -f outputs/v6_round1/logs/run_v6.log          # 或在 Web 终端直接看
bash run_v6.sh status                              # 随时另开一个终端问"跑到哪了"
```

进度行长这样（每个单元两行边界 + 每轮一行 + 评估两行）：

```
前置检查通过｜数据 .../Data｜起点权重 12/12 .../weights/v5_joint｜标注池 outputs/v6_round1/selection/selection.json
设备：Tesla T4 2.6.0+cu124
== 本次共 84 个单元
------------------------------------------------------------------
[1/84] source_continue_f0_s0 开始 09:41:41
源训练 1/30：CE=0.0210，源验证 F1=0.9219，Accuracy=0.9286，best=1，耗时=4.1秒
...
[1/84] 完成，本单元 148s，累计 148s，剩余约 204 分钟（按均值推算）
```

单元顺序固定：`baseline` 12 个纯评估 → `continue` 12 个 → `adabn` 24 个 → `adapt` 48 个；`all` 跑完再自动 `summary`（96 个单元 = 60 完整训练 + 24 无梯度 + 12 基线评估；`status` 的 96 里含基线，分动作跑时总数会相应变小）。剩时间按已完成单元的均值推算，第一个单元之后就有意义。

也可以分开跑，互不影响（已存在的产物会跳过，中断后重跑同一命令即续上）：

```bash
bash run_v6.sh baseline && bash run_v6.sh continue && bash run_v6.sh adabn && bash run_v6.sh adapt && bash run_v6.sh summary
```

## 6. 时间预算（用实测推，不用估计）

本机 `GTX 1650 Ti`（torch 2.6.0+cu124）实测：一个 `ce_adapt` 完整单元 **≈ 3.9 分钟**（训练 30 轮 ×155 步，每轮 6–8 秒；留出评估两通道约 40–50 秒）。按同一模型规模与步数折算：

| 动作 | 单元数 | 单元成本 | 合计 |
| --- | ---: | --- | ---: |
| `baseline`（纯前向） | 12 | ~10 秒 | ~2 分钟 |
| `continue`（只源域，单 batch/步） | 12 | 约 `adapt` 的 2/3 | ~25–30 分钟 |
| `adabn`（无梯度前向，不反传） | 24 | 明显更快，估 1–1.5 分钟 | ~30 分钟 |
| `adapt`（ce + ce_mmd） | 48 | ~3.9 分钟 | ~3.1 小时 |

合计 **约 4–4.5 小时串行**（本机口径；T4 算力同级或略快，显存 16 GB 更宽裕）。协议草案里写的"约 3.0 h"是按 v5 的更少流程估的，比实测偏乐观——这只影响你排班，不影响任何判据。想压时间可以在云端只跑 `adapt` 一个动作先出主结果，`adabn`/`continue` 的控制项随后补，但**配对链要求同 `fold/seed/来源/通道` 双边齐全**，缺控制臂的那几对暂时算不出来，不能拿别的折的种子补。

## 7. 失败与重跑

- 默认 `set -e`：第一个失败单元就停，并打印重跑命令。想整批不中断：`KEEP_GOING=1 bash run_v6.sh all`（失败单元会打印在进度行里，跳过继续）。
- 单独重跑一个单元并留后缀：`bash run_v6.sh one mmd_adapt 48k_DE 2 1 retry1`，产物落在 `train/48k_DE_mmd_adapt_f2_s1_retry1`，正式目录不被覆盖。
- `train.py`/`evaluate.py` 自己拒绝写入非空目录，所以不会静默覆盖已有结果；重跑同一单元必须换后缀。
- 只有一个单元反复失败时才去看它的 `progress.pt` 与终端报错，不要动别处。

## 8. 云端不要做的三件事

1. **不要重跑 `selection.py`**。池是冻结的协议组件，`selection.json` 已随仓库带上；重算依赖 scikit-learn 版本（本机 1.9.0 复现 k=10/12），版本不同可能给出不同的簇，那才是真的破坏可比性。若确实要复算验证，用 `requirements.txt` 的固定版本，并把差异记进文档而不是改池。
2. **不要提交 `outputs/v6_round1/train/`**（300 MB 权重，`.gitignore` 已排除），也**不要改 `Data/` 里任何文件**（数据根只读，与 v4 同源）。
3. **不要改判据、`k`、容差、折数或 seed 数**，也不要临时加臂；结果没到 95% 时按 `docs/v6运行冻结记录.md` §7 的零算力错误结构分析走。

GPU 与 CPU、不同 GPU 之间的逐位结果不保证一致（cuDNN 核与归约顺序差异），要求的是**同一台机器内同 `fold/seed` 可重复**（`seed_everything` 已设 `deterministic`）；判据与配对链口径不变。本机两次冒烟（同 `fold0/seed0`）逐轮 `源CE/目标CE/源验证 F1` 完全一致，说明这条在同型号 GPU 上是成立的。

## 9. 跑完之后

`bash run_v6.sh summary` 生成 `outputs/v6_round1/summary/`：

- `criterion.csv` / `report.md` 的"判据核对"表：每个臂按来源的记录级准确率均值、样本标准差（`ddof=1`）、最差格、过 95% 格数、是否达标；
- `grouped.csv`：臂 × 训练来源 × 测试来源 × 通道的均值±标准差；
- `detail.csv`：逐格值（`fold`×`seed`×`通道`，共 96 行级别）；
- `paired_comparisons.csv`：六对配对链的逐格差值，负增量完整保留。

建议把 `summary/` 与 `eval/`（合计约 1–2 MB，不含权重）提交回仓库，这样云端跑完的结果和本地文档在一起；`train/` 里只留 `config.json`+`history.csv` 值得回看的话单独取，不要整目录提交。
