# v5 复用与迁移清单

> 配套 `../agents.md`（原则：实验完整，工程简单）与 `v6协议草案.md`（协议与判据）。
> 迁移方向单向：v5 → v6。**复制文件后按 v6 改，不 import v5 路径**（v5 已冻结，跨目录 import 只会让两边耦合）；数据与权重例外，按绝对路径只读引用。
> 迁移的第一动作是**做减法**：v5 里为多协议、多批次、多表征、多控制项而生的分支，进 v6 先删，不留兼容余地。

## 2. 复制后要改（都是删分支）

**`dataset.py`**
- 删 `TARGET_QUOTAS`、`ARM_QUOTAS`、`STRATIFIED_OR`、`SOURCE_INDEX`、`ARM_NAMES`、`split_target_files`（v1）、`split_target_v2`（v2 的元数据分层四档）。
- 新增一个函数 `target_split_v6(data_root, selection_path)`：读 `selection.json` 的池，返回 `{source: {"pool": [...], "test": 全部 − 池}}`。保留三条断言（数据完整性，不是防御）：池与测试不重叠、池内文件属于该来源、每个 `类×尺寸×位置` 层的测试文件数写进返回值（v6 实测无空层，但规则不保证，必须可看见）。
- `split_source_files` 与四折逻辑不动。

**`preprocessing.py`**
- `REPRESENTATIONS` 收成 `("logspec512",)`；删 `ENVELOPE_BANDS`/`ENVELOPE_FILTER_*`/`select_envelope_band`/`envelope_spectrum`/`build_envelope_feature_set`，`build_record_features` 里去掉包络分发。`logspec4096` 一并删（本轮单表征）。
- 保留 `predict_features` 的调用方需要吗？v6 本轮不做单信号预测交付 → 一起删，阶段二要用再从 v5 取。

**`experiment.py`**
- 删 `prepare_target`、`prepare_target_v2`、`split_payload`、`split_payload_v2`（都绑死 `adapt_arm` 与 `label_ratio`）。
- 新增 `prepare_target_v6(data_root, fold, split_seed, target_source, selection_path, repr_config=None)`：只给池内文件建 DE/FE 特征，`test` 只保留文件列表不读信号（沿用 v5"unused/test 不进特征构建"的写法）。

**`train.py`**
- `--protocol`（v1/v2 分支）、`--adapt-arm`、`--label-ratio`、`--target-split-seed`、`--representation`、`--mmd-bandwidth` **全部删除或收窄**：臂只剩 `--mode {source, source_continue, adabn, ce_adapt, mmd_adapt}`，表征写死 `logspec512`，MMD 用固定核，`tsplit` 塌缩后不需要该参数。
- `--source-checkpoint` 保留（要读 v5 的 `joint` `last.pt`）；`--selection-rule` 固定 `last`，参数可留但默认不再参与选择。
- 落盘 `config.json` 必须补 `checkpoint_kind` 与 `checkpoint_epoch`（v5 缺 101 个的教训），并把 `pool_file_count`／`actual_label_ratio` 一起写下。

**`trainer.py`**
- 删 `train_source_ce_target_bn`、`train_target_only`；**保留 `train_source_continue`**（本轮加回的源续训控制）和 `train_adabn`（无标注 BN 控制）。
- `train_source_continue` 的冻结参数照 v5 抄：新建 Adam `1e-4`、`bs=64`、30 轮、`steps_per_epoch=ceil(S_ref/64)`（**按折取该折源 config**：f0/f2/f3=155、f1=156，对应 `updates` 4650/4680）、`lambda_mmd=0`、不喂目标数据。**必须逐字段等于适配臂的那一份**（v5 `train/f{fold}_s{seed}_source_continue/config.json` 就是样板，已核对 12/12 与同折 `ce` 预算一致），否则它就不是"额外更新步数相同"的控制。
- `SCHEMA_VERSION` 保留常量但**不做版本兼容分支**：v6 只读 v6 自己写的版本，读 v5 checkpoint 走 `load_checkpoint` 的状态字典加载这一条路。

**`evaluate.py`**
- 删 `_summarize_runs_v1`、`_v2_all_pairs` 里的跨表征配对、`_v2_method_key` 的四档臂映射。
- `_v2_pairs_for_cell` 重写为 v6 固定链，就六对：`source_continue vs joint`、`adabn vs joint`、`ce vs joint`、`ce vs source_continue`、`ce vs adabn`、`mmd vs ce`；每条只在同 `fold/seed/来源/通道` 且**双方测试列表逐项一致**时才计算——这条一致性校验保留（v5 用 `eval_info.json` 的 `test_files`，见 v5 `evaluate.py:245`、`:369`、`:594`）。
- 修 v5 遗留缺陷：`grouped.csv` 的 `records_per_run` 写实际值（v5 只在 `members[0]` 取了一个数），标准差一律 `ddof=1`。

**`run_stage1.py` / `run_round2_queue.sh`**
- **不迁移**。v6 的 48 流程用一个 shell 循环（`run_v6.sh`：来源 × 臂 × fold × seed 四层 `for`，先 `train.py` 再 `evaluate.py`，`set -euo pipefail`）。删掉 v5 的 `build_v2_plan`/`build_p2_plan`/`build_v2_p3_plan`/`build_v2_p4_plan`/`_output_lock`/`_isolate_incomplete`/`--batch-index`/`--num-batches`/进度状态机。
- 失败处理沿用 v5 的做法：单独重跑那一个目录，输出目录加 `_retry1` 后缀，不引入调度器。

**`predict.py`**
- 不迁移（本轮无预测交付需求）。

## 3. 明确不迁移（防止"顺手带过来"）

v5 的 `outputs/` 全部产物；`paired`/`natural`/`transductive` 痕迹；`envelope4096` 与 `logspec4096` 全链路；`median` 核 MMD；`target_only`；`src_ce_target_bn`；`r10`/`r20`/`random13`/`stratified13` 四档划分与它们的配对链；分批编排与 `progress` 状态机；`--protocol` 双协议分支。（`source_continue` 不在此列，本轮加回作控制臂，见 §2。）

## 4. 唯一跨版本复用的产物

- v5 `outputs/stage1_v2_round2/train/f{fold}_s{seed}_joint/last.pt`，12/12 齐备（已逐个核对），`representation=logspec512`、`selection_rule=last`；**预算按折不同**：`s_ref`/`steps_per_epoch` = f0 9863/155、f1 9983/156、f2 9866/155、f3 9861/155。v6 适配一律从这里起，**不重训源模型**；`S_ref` 从对应源 `config.json` 读，不按目标文件数重算。
- v5 的 `predictions.csv`/`metrics.json` **不复用**：v6 测试列表是 `全部 − 池`，包含 4–5 个原本属 v5 标注池的文件，不是 v5 已评列表的子集，所以基线与 BN 控制要在 v6 列表上各跑一次无梯度前向。
- 读取 v5 权重时按 `last.pt` 文件名 + `selection_rule=last` 认定（v5 config 没有 `checkpoint_kind`），这条依赖写进 `frozen_plan_v6.json`，不为此加校验层。

## 5. 新增文件（就两个）

- `selection.py`：特征 → 短记录过滤 → silhouette 曲线 → 取最小够 95% 峰值的 `k` → 每簇 medoid（单例排最后）→ 写 `outputs/v6_round1/selection/selection.json`。只读 `dataset.py`/`preprocessing.py`，不加载权重，不写第二个产物。
- `run_v6.sh`：四层 `for` 循环跑 48 流程与评估，`train`／`evaluate`／`summary` 三个动作。

## 6. 迁移执行顺序（每步有验收，不通过不进下一步）

1. 复制 §1 文件 → 做 §2 的减法 → `import` 全部模块无错，`dataset.py`/`preprocessing.py`/`trainer.py` 的 `_self_check()` 手动跑通（不当启动钩子）。
2. 写 `selection.py` → 生成 `selection.json` → **复算 `v6协议草案.md` §3 的池与覆盖**（原期望 k=10/13、K=10/13、`类×尺寸` 9/9、无空层）；与文档数字不一致就以脚本为准并回写文档，然后才写 `docs/v6运行冻结记录.md`。**（已完成 2026-10-11：`12k_FE` k=10/K=10 与文档逐项一致；`48k_DE` 短记录命中 6 个、候选 46、k=K=12、`类×尺寸` 9/9、`类×尺寸×位置` 12/13、无空层——差异全部按"以脚本为准"回写草案 §2.2/§2.3/§3/§4/§8/§9.5，并记进 `docs/v6运行冻结记录.md` §1 与 `frozen_plan_v6.json`。第 1 步的模块自检与 import 亦已通过。）**
3. 冒烟一个流程：`fold=0 seed=0`、`12k_FE`、`ce` → 产物齐全（`config.json`/`last.pt`/`history.csv`/`split.json` + `eval/metrics.json`/`predictions.csv`），`checkpoint_kind` 正确，测试列表逐项一致校验通过。
4. 跑全部 60 个完整训练流程（`ce`/`ce_mmd` 各 24、`source_continue` 12；串行约 3.0 h）与 24 个 `adabn` 无梯度运行，逐目录只读验收。
5. `summary` 出表：按来源给均值＋样本标准差＋逐格值，六对配对的负增量完整保留，对照 §1 判据（按来源均值 ≥95%）。

## 7. 别把 v5 的遗留缺陷一起搬过来

| 缺陷 | v5 表现 | v6 做法 |
| --- | --- | --- |
| `checkpoint_kind` 缺失 | 101 个流程无该字段，只能靠文件名推断 | 新目录必写 `checkpoint_kind`/`checkpoint_epoch` |
| `records_per_run` 取单值 | `grouped.csv` 一格只代表一个 run | 按实际成员数写 |
| 标准差口径混用 | 曾把总体口径当样本口径 | 一律 `ddof=1` |
| 跨版本数字相减 | 首轮/第二轮列表不同 | 禁止相减，只在 v6 列表内配对 |
| 预注册链缺环 | `envelope ↔ logspec512` 事后补算 | 六对配对链训练前写死，中途不增删 |
| 控制臂名不副实 | — | `source_continue` 的 `learning_rate`/`epochs`/`steps_per_epoch`/`updates`（1e-4／30／155／4650）必须与 `ce` 逐字段相同，否则"额外更新步数相同"这句话不成立 |
| 划分维度掩盖反转 | `tsplit` 曾推翻包络谱推荐 | 本轮 `tsplit` 塌缩，无法再靠这条轴查反转——已作为已知代价写进 §4 |
